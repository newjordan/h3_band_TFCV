### Code switches added (all default off, in `blockout/piano.py`; `PIANO_OVR` JSON sets them)
- **`PRESS_OVERSHOOT`:** the press target sits this far below the key bed.
- **`REPAIR_ITERS` / `REPAIR_W`:** a verify-and-repair loop around pass B (`_pass_b`). It boosts a missed note's finger around its onset.
- **`REACH_SPLIT`:** `_reach_split` in `split_hands`.
- **`ROLL_STAGGER` / `ROLL_V` / `ROLL_LAG_MAX`:** in `slices`. It uses note copies, so the score's onsets are unchanged.
- **`RIG_LIMITS`:** an env var with joint-limit overrides (`rig/skeleton.py`).

## Pitfalls hit this session (avoid)
- **`pgrep -f` / `pkill -f` with a pattern that appears in your own command line matches your own shell.** That killed my command twice. Use `[x]` bracket patterns, PIDs, or script files.
- **`lab/run.py` puts the `env` field unquoted into the shell.** Single-quote any JSON in it, as E32/E33 do.
- **Code changes only between runs.** Remotes sync at run start, but local windows import per window. Develop in `~/h3b_dev` and merge between runs.
- **Pausing a run:** kill queue.sh, run.py *and* the `eval_suite window` grandchildren, plus `ssh <host> pkill -f lab_<ID>_w_` on sparky and turbo. Then delete `lab/runs/<ID>`.
- **Write notebook numbers only after printing the results.** Twice this session I typed an entry before reading the scores; both were corrected and marked in the notebook.
- **Workers spawned from the sandbox shell** (`nohup ... &`) survive the turn. Arm a Monitor on `lab/queue.log` and `probes.log` for DONE, success and error lines.
